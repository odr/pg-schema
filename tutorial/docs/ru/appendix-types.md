# Типы данных

Для каждого поля в типах данных компилятор проверяет, подходит ли его тип
Haskell к типу колонки в базе. В этом приложении собраны соответствия типов,
которые `pg-schema` поддерживает сама, и показано, как добавить свои.

## Как устроена проверка

Из сгенерированного `Sch.hs` компилятор знает про каждую колонку три вещи:
имя её типа в PostgreSQL (например, `"pg_catalog" ->> "text"`), допускает ли
она `NULL` и описание типа `TypDef`. Описание типа состоит из категории типа
(как в системном каталоге `pg_type`: `B` — логический, `N` — числовой, `S` —
строковый, `D` — дата и время, `E` — перечисление, `A` — массив, `U` —
прочие, например `json`, `uuid`, `bytea`), типа элемента для массивов и
значений для перечислений.

Сначала проверяется `Maybe`: у колонки, которая допускает `NULL`, тип поля
должен быть `Maybe t`, а у обязательной — не должен. Затем для оставшегося
типа `t` должно найтись уравнение открытого семейства типов `CanConvert1`:

```haskell
type family CanConvert1 sch (tab :: NameNSK) (fld :: Symbol) (tn :: NameNSK) (td :: TypDefK) t :: Constraint
```

Его аргументы — схема, таблица, колонка, имя типа колонки, описание этого
типа и тип Haskell. Если подходящего уравнения нет, компилятор сообщит
`Could not solve: CanConvert1 …` и перечислит в сообщении все эти аргументы.
Массивы (`PgArr t`) и перечисления (`PGEnum`) библиотека обрабатывает
отдельно: для массива проверяется тип его элемента.

## Поддерживаемые типы

Если колонка допускает `NULL`, тип из таблицы оборачивается в `Maybe`.

| Тип в PostgreSQL | Тип в Haskell |
|------------------|---------------|
| `boolean` | `Bool` |
| `smallint` (`int2`) | `Int16` или `Scientific` |
| `integer` (`int4`) | `Int32` или `Scientific` |
| `bigint` (`int8`) | `Int64` или `Scientific` |
| `real`, `double precision` | `Double` или `Scientific` |
| `numeric` | `Scientific` (а также `Fixed k`, но без проверки точности) |
| `text`, `varchar`, `name` | `Text` |
| `"char"` | `PgChar` |
| `citext` | `CI Text` |
| `date` | `Day` |
| `time` | `TimeOfDay` |
| `timestamp` | `LocalTime` |
| `timestamptz` | `UTCTime` или `ZonedTime` |
| `uuid` | `UUID` |
| `bytea` | `Binary ByteString` (строгий или ленивый) |
| `json`, `jsonb` | любой тип с `FromJSON` и `ToJSON` |
| enum | `PGEnum Sch ("схема" ->> "тип")`, сгенерированный в `Sch.hs` |
| массив | `PgArr t`, где `t` — тип элемента |

`Scientific` берётся из пакета `scientific`, `CI` — из `case-insensitive`,
`UUID` — из `uuid`. Типы даты и времени, `uuid` и `citext` поддерживаются,
пока включены флаги пакета `pg-schema` `time`, `uuid` и `case-insensitive`;
по умолчанию все три включены.

## Свои типы

Поскольку `CanConvert1` — открытое семейство, к нему можно добавить свои
уравнения. Так можно, например, хранить адрес электронной почты в отдельном
типе-обёртке, а не в голом `Text`. Для этого нужны две вещи.

Во-первых, сам тип должен уметь передаваться в базу и обратно. Для корня
`selectSch` и операций с одной таблицей значения передаёт `postgresql-simple`,
поэтому нужны `FromField` и `ToField`. Во вложенных ветках результата и в
операциях `*JSON` данные идут через JSON, поэтому нужны ещё `FromJSON` и
`ToJSON`. Для обёртки все они выводятся через `deriving newtype`.

Во-вторых, нужно уравнение `CanConvert1`, которое разрешает этот тип для
нужных колонок. Оно может быть общим, для всех колонок типа `text` во всех
таблицах (`CanConvert1 sch tab fld ("pg_catalog" ->> "text") ('TypDef "S" x y) Email`),
а может быть и узким, только для одной колонки одной таблицы. Узкое уравнение
полезно тем, что компилятор не даст по ошибке записать `Email` в какое-нибудь
другое текстовое поле:

```haskell
--8<-- "app/app/Tut/Types.hs:types-email"
```

Теперь `Email` можно использовать везде, где встречается колонка
`users.email`: во входных данных, в результате и в условиях. Пример
выполняется на данных главы [«Select»](04-select.md):

```haskell
--8<-- "app/app/Tut/Types.hs:types-email-use"
```

```text
--8<-- "out/tutorial.txt:types-email"
```

??? note "SQL, отформатированный для чтения"

    ```sql
    --8<-- "out/tutorial.txt:types-email-sql"
    ```

А для колонки `users.name`, у которой тот же тип `text`, `Email` уже не
подойдёт:

```
• Could not solve: ‘CanConvert1
                      Sch.Sch
                      (NameNS "tut" "users")
                      "name"
                      (NameNS "pg_catalog" "text")
                      (TypDef "S" Nothing '[])
                      Email’
    arising from a use of ‘selectSch’
```

Точно так же можно поддержать тип PostgreSQL, которого нет в таблице выше,
например `inet` или домен, объявленный в вашей базе. Нужен тип Haskell с
инстансами `FromField` и `ToField` (и JSON-инстансами, если колонка будет
участвовать во вложенных ветках или в `*JSON`) и уравнение `CanConvert1` с
именем этого типа в базе и его категорией. Имя и категорию проще всего
посмотреть в сгенерированном `Sch.hs`: там для каждого используемого типа есть
уравнение `TTypDefSch`.
