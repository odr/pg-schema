# Учебник по pg-schema (черновик)

[`pg-schema`](https://hackage.haskell.org/package/pg-schema) — это библиотека
для работы с PostgreSQL из Haskell, в которой правильность запросов
проверяет компилятор. Идея в том, чтобы один раз извлечь схему базы в
Haskell-модуль и дальше строить `select`, `insert`, `update` и `delete` с
проверками на этапе компиляции. Тогда ошибки в именах таблиц, колонок и
связей, в типах значений и в форме вложенных данных обнаруживаются ещё до
запуска программы, а не в тестах и не в работе.

В обычном приложении такие ошибки встречаются постоянно: опечатка в имени
колонки, связь не с той таблицей, параметр не того типа, вложенные данные не
той формы. Каждую из них приходится ловить при выполнении запроса. С
`pg-schema` все они становятся ошибками компиляции, а после изменения схемы
базы компилятор сразу показывает все места в программе, которые нужно
поправить.

Описание схемы генерируется прямо из живой базы PostgreSQL. По нему
`selectSch` читает данные вместе со связанными строками, переходя по
внешним ключам, а `insertJSON` и `upsertJSON` записывают целое дерево данных
— например, проект вместе с задачами — одной операцией. Поддерживаются
перечисления, `json` и `jsonb`, массивы и составные ключи.

Вот как выглядит типичный запрос. Сначала описывается аннотация для
корневой таблицы, а затем выполняется `selectSch`:

```haskell
--8<-- "app/app/Tut/Why.hs:why-ann"

--8<-- "app/app/Tut/Why.hs:why-select"
```

Тип результата задаёт, какие поля и связи нужно прочитать: здесь это проекты
со списком их задач. `qRoot` задаёт условия для корневой таблицы `projects`,
а `qPath` — для ветки задач. Весь результат читается одним SQL-запросом, а
кроме строк `selectSch` возвращает текст запроса и его параметры. Если
ошибиться в имени таблицы, колонки или связи, программа просто не
скомпилируется. Как всё это устроено, мы разберём в следующих главах.

## Требования

- GHC ≥ 9.10: библиотека использует видимые аргументы типов
  (`selectSch (MyAnn "users") …`). Tutorial проверяется на GHC 9.12.4
  (см. `cabal.project`).
- PostgreSQL и `psql`/`createdb` в `PATH`.
- Расширения GHC. Примеры написаны на `GHC2024`, в который уже входят
  `DataKinds` и `TypeApplications`. Дополнительно нужны:
    - `OverloadedStrings` — имена полей и связей задаются строками;
    - `BlockArguments` — для `qRoot do …` и `qPath "…" do …`;
    - `TypeFamilies` и `UndecidableInstances` — для своего ренеймера;
    - `DuplicateRecordFields` — если у нескольких record-типов есть
      поля с одинаковыми именами (например, `title` у проекта и задачи).
