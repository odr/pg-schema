# Зачем нужен pg-schema

[`pg-schema`](https://hackage.haskell.org/package/pg-schema) — это библиотека для работы с PostgreSQL с контролем запросов в compile-time.

Главная идея:
- схема базы один раз извлекается в Haskell-модуль
- дальше `SELECT/INSERT/UPDATE/DELETE` строятся с проверками на этапе компиляции
- ошибки в именах таблиц, полей и связей ловятся до запуска приложения
- действия над связанными наборами данных выполняются одной sql-операцией

## Что это дает на практике

Обычный риск при работе с SQL в приложении:
- опечатка в названии поля
- неправильная связь между таблицами
- несовместимый тип параметра
- невалидный shape данных при вложенных вставках

С `pg-schema` эти классы ошибок переносятся из runtime в compile-time.

## Ключевые возможности

- Генерация type-level схемы из живой PostgreSQL БД
- Типобезопасный `selectSch` с навигацией по связям (`qPath`)
- Вставка/апдейт дерева данных (`insertJSON`/`upsertJSON`) за один запрос
- Поддержка enum, json/jsonb, массивов (`PgArr`) и составных ключей

## Минимальный пример

1. Генерируем модуль схемы `Sch`.
2. Описываем `Ann` для корневой таблицы.
3. Выполняем типобезопасный `selectSch`:

```haskell
type MyAnn tab = 'Ann RenamerId Sch 5 ("tut" ->> tab)

(rows :: ["title" := Text :. "tasks_project_id_fkey" := ["title" := Text :. "priority" := Int32]], (sql, params)) <-
  selectSch (MyAnn "projects") conn $ qRoot do
    qWhere $ "status" =? Project_status_active
    qPath "tasks_project_id_fkey" do
      qWhere $ "priority" <? (50 :: Int32)
```

Тип результата задаёт, какие поля и связи читаются: здесь это проекты
со списком их задач. `qRoot` задаёт условия для корневой таблицы `projects`,
а `qPath` — для ветки задач. Кроме строк `selectSch` возвращает текст
SQL-запроса и его параметры: `(rows, (sql, params))`.
